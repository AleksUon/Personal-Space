# Personal Space — этап 2: защищённый локальный дневник

**Windows, Python 3.11+, PySide6, SQLite, cryptography.** Приложение работает без Интернета, регистрация не нужна.

## Как запустить
1. Установите Python 3.11+ с python.org, отметьте «Add Python to PATH».
2. Распакуйте архив; дважды щёлкните `start_windows.bat`.
3. При первом запуске скрипт установит PySide6 и cryptography (Интернет нужен только для установки библиотек).
4. Задайте мастер-пароль **не короче 12 символов** и сохраните его в надёжном месте. Без пароля доступа к данным не будет; функция восстановления пароля отсутствует.

Данные хранятся в `%USERPROFILE%\PersonalSpaceData\vault.psv`. В старом файле `%USERPROFILE%\PersonalSpaceData\personal_space.sqlite3` могут оставаться данные из этапа 1. **Приложение не удаляет прежнюю базу автоматически.**

## Что нового в этапе 2
- Мастер-пароль при создании хранилища и каждом новом запуске.
- Шифрование AES-256-GCM, derivation ключа Scrypt (N=32768, r=8, p=1, 16-byte salt). Для каждого сохранения — новая соль и nonce.
- SQLite создаётся и работает **в оперативной памяти**; на диск помещается только шифрованный снимок `vault.psv`, записываемый атомарно. Имена дневников, тексты записей и индекс не сохраняются открытым текстом в файле базы.
- Шифрованные резервные копии `.psbackup` и проверка расшифровки/целостности.
- Восстановление копий со своим паролем (можно использовать пароль старой копии после смены мастер-пароля).
- Смена мастер-пароля с проверкой старого.
- Ручная блокировка Ctrl+L и автоблокировка после 5 минут бездействия (можно поменять в меню «Безопасность»).
- Перенос старой незашифрованной базы первого этапа в новое хранилище — «Файл → Импортировать старую базу MVP». Выполняется только в **пустой** защищённый профиль. Исходный файл не изменяется.

## Что сохранено из первого этапа
Несколько независимых дневников, редактор, списки и ссылки, отмена/повтор, Ctrl+S, автосохранение ~900 мс, локальный поиск (включая кириллицу), две темы, удаление с подтверждением, отдельная дата события/пробуждения.

## Важные ограничения безопасности
- Это прототип, не проходивший независимый аудит безопасности. Перед хранением наиболее чувствительных данных необходимо внешнее тестирование.
- Пароль **невосстановим**: отдельного recovery key нет.
- Текст и ключ могут находиться в оперативной памяти работающего процесса, дампах, системном файле подкачки или гибернации. Python/Qt не дают надёжной гарантии очистки всех копий из памяти. Для защиты диска и swap рекомендуется включить BitLocker в Windows.
- Никакого облачного обмена или синхронизации пока нет.
- Старые `.sqlite3`, файлы `-wal`/`-shm`, `pre_restore.sqlite3` и ZIP-копии этапа 1 **остаются незашифрованными**. После проверки импорта самостоятельно примите решение об их удалении и об удалении их резервных/облачных копий; обычное удаление не гарантирует безопасное стирание SSD.
- Текущая версия хранит всю базу в RAM и перезаписывает шифрованный снимок при изменении. Не подходит для огромных баз и тяжёлых вложений; вложения как отдельные файлы пока не поддерживаются.
- Настройки темы и периода блокировки хранятся отдельно в JSON и не содержат записей.
- Приложение не обеспечивает защиту от вредоносного ПО с доступом к активной пользовательской сессии.

## Проверки
`python -m unittest -v test_security`

Проверяются шифрование и обнаружение повреждения файла, неправильный пароль, сохранение/разблокировка, смена пароля, шифрованная резервная копия и импорт старой базы. Полное GUI-тестирование на Windows требуется отдельно.
